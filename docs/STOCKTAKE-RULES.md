# 库房盘点对账规则

## 使用者

库房管理员按库位进行每日盘点对账，并签发差异单。

## 对账口径

1. **在途优先，避免两边重复找货**：样品有发出凭据、盘点截点前尚未签收的，先记在途，不算短缺。
2. **逾期未签收记发出库位短缺**：在途样品过了凭据上的约定签收日仍未签收，记发出库位（`from_location`）短缺，原因码 `TRANSIT_OVERDUE`。
3. **重号独立列示，差异不相抵**：同一件样品被两个库位（或同一库位多条盘点记录）同时盘到，报重（`DUPLICATE`）。重号、短缺、多出分别独立列示，不得互相抵消。
4. **截点采信**：差异单只认盘点截点之前（严格早于截点日）已登记的发出/签收凭据。签收与盘点同时提交（登记日等于截点日）或截点之后登记的凭据一律不采信，记入 `ignored_vouchers`。
5. **已签收转移**：截点前已签收的转移，责任库位转到目的库位，按目的库位核对。
6. **普通短缺与多出**：无有效在途凭据且责任库位未盘到，记 `NOT_COUNTED` 短缺；实物出现在非责任库位，分别记 `LOCATION_MISMATCH` 短缺与多出，不相抵；账面无记录却盘到，记 `SURPLUS` 多出。
7. **幂等签发**：同一盘点单号（`stocktake_id`）重试提交不重复登记，返回原差异单；同号但内容不同的提交返回 `STOCKTAKE_CONFLICT`（409），拒绝覆盖。

## 差异类型

| 类型 | 含义 |
|---|---|
| `IN_TRANSIT` | 已调出未签收且约定签收日未过，记在途不计短缺 |
| `SHORTAGE` | 短缺，原因码 `TRANSIT_OVERDUE` / `NOT_COUNTED` / `LOCATION_MISMATCH` |
| `DUPLICATE` | 同一样品在多处盘到，重号独立列示 |
| `SURPLUS` | 多出，独立列示，不与短缺相抵 |

## 输入边界

- 截点字段 `cutoff` 为 ISO 日期；凭据 `registered_at`、`due_date` 同为 ISO 日期。
- 标识字段（库位、样品号、凭据号）按文本处理，前导零保留。
- 必填字段缺失返回 `BAD_REQUEST`（400）。
